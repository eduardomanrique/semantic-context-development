## Current testing posture

Executable tests should cover at least the following story 1 expectations:

- new claims start in `DRAFT`
- owners can edit claims while in `DRAFT`
- submission is blocked when `description` is empty
- submission is blocked when `amount` is less than or equal to zero
- submission is blocked when `category` is missing
- successful submission changes status to `SUBMITTED`
- employees cannot edit a claim after submission
- managers can review only claims in `SUBMITTED`
- manager review changes status to `APPROVED` or `REJECTED`
- owners can reopen rejected claims and return them to `DRAFT`
- reopened rejected claims can be edited as corrected drafts but cannot be resubmitted
- approved claims remain read-only and paid claims remain terminal
- finance users can mark only `APPROVED` claims as `PAID`
- marking a claim paid records who paid it and when
- once paid, the claim is terminal in the current slice
- employees can list and view only their own claims
- managers and finance users can list and view all claims
- claim lists return newest claims first and do not filter in the current slice
- unauthenticated users cannot access protected claim flows
- only admins can create users
- authenticated username replaces explicit actor or viewer identifiers in protected flows

Each executable test should link back to:

- semantic definition
- planned test coverage
- implementation area
